# 類比測試集可答性檢查（階段 1，#20）

- 腳本：`scripts/stage2_lab05_analogy_answerability.py`｜資料：`benchmarks/analogy_v2.json`（與 v2 相同的 36 題）
- 兩種題型：(a) 候選句排序（與 v2 相同協定）；(b) 三選一選擇題：給三條規律的描述，只給領域名稱與目標句，問它屬於哪條規律。每題換 3 種選項順序，**至少 2 次答對才算對**，以排除位置偏誤
- 機率水準 12/36；完整輸出：`run.log`

## 依事先登錄標準的判讀
- **7B 選擇題第 2 階段 83% ≥ 80% → 題目可答、具分辨力。** v2 以第 2 階段為主要指標的結論（雙腦 B1 42%、核心假設在此規模下未獲支持）成立
- **第 3 階段（67%）與反向關鍵字題（5/9）介於門檻之間**，需要逐題檢查。7B 答錯的題目集中在：
  - 第 3 階段的結局在三條規律之間重疊（「暫停／停機／切換備用」同時符合洩壓、備援接手與緊急停機），例如「设备只能丢弃新包，连接被重置」「随后看门狗超时，强制重启服务」
  - 部分供給枯竭題寫得像阻塞，例如「已缓冲的视频片段一秒秒播完」「空闲堆空间被新对象一块块吃掉」
  - 反向關鍵字題中有幾題本身語意模稜兩可，例如「供血的动脉突然被血栓堵住了」字面上就是阻塞
- **排序協定（候選句條件機率）不是好的能力指標**：7B 零樣本只有 20/36，與 0.5B 相同；它受句子流暢度影響太大。之後與語言模型比較時，以選擇題作為能力上限的參考

## 對階段 3 的影響
- 新資料的每一題須經 7B 選擇題檢查（換順序多數答對），未通過的題目修改或剔除
- 第 3 階段三條規律的結局要明確區分：阻塞增壓 → 洩壓或阻斷；供給枯竭 → 備援接手；正反饋 → 失控崩潰
- 反向關鍵字題重寫，避免本身語意模稜兩可
